# 자료집 검수

검수는 고치는 일이 아니라 **판정을 남기는 일**이다. 무엇이 왜 틀렸는지 기록으로 남아야 분석가가 정확히 고치고, 같은 실수가 다음 섹터에서 줄어든다.

## 기준

- `accounts/tech/planning/analysis-workflow.md`의 「통과 조건」과 「출처 표기 원칙」
- `accounts/tech/planning/orchestration.md`의 「섹터 완료 조건」

## 섹터마다

1. `dossier.md`의 수치·날짜·인용을 모두 뽑는다.
2. 적힌 출처 URL을 연다. curl로 열리면 curl로. 안 열리면 "확인 불가 · Chrome 재조사 필요".
   - Firecrawl은 **웨이브 전체에서 2크레딧 이하**, 게시물 각도의 핵심 근거가 되는 수치에만.
3. 비교 기준을 놓치지 않는다: 퍼센트와 퍼센트포인트, 연환산과 실제, 회사 자체 측정과 독립 측정, 시뮬레이션과 실제.
4. 5절 분석이 근거를 넘어서는 문장, 6절 각도가 기대는 근거가 "확인 불가"인 경우를 찾는다.
5. 섹터 완료 조건을 하나씩 체크한다(`wc -l brief.md`로 30줄 이하 확인 포함).

## review.md 형식

```
# <NN> <섹터> — 검수
판정: 통과 / 수정 필요

| # | 주장 | dossier 값 | 원문 값 | 판정 (일치·다름·확인 불가) | 출처 URL |

## 섹터 완료 조건
- [ ] ...

## 수정 필요 사항
1. [책임: 수집 / Chrome / 분석] <무엇이 · 어디서(절·파일) · 원문 값과 URL>

Firecrawl 사용: N크레딧
```

"확인 불가"가 핵심 근거에 있으면 판정은 "수정 필요"다. 확인하지 못한 것을 통과로 세면 검수의 의미가 없다.

## 책임 단계 붙이기

수정 필요 사항마다 **틀린 값이 처음 들어온 곳**을 책임 단계로 적는다. 지휘자는 이것을 보고 고칠 사람을 부른다. 분석가는 1–3절과 `chrome-findings.md`를 고칠 수 없으므로, 책임이 잘못 적히면 반려가 헛돈다.

| 책임 | 기준 | 다시 부를 에이전트 |
|---|---|---|
| 수집 | `dossier.md` 1–3절의 값·출처가 틀림, 1차 출처 누락 | `report-collector` |
| Chrome | `chrome-findings.md`의 값·출처가 틀림, "확인 불가 · Chrome 재조사 필요" | `web-researcher` |
| 분석 | 4–7절이 1–3절·Chrome 결과를 잘못 옮김, 근거를 넘어선 해석, 조건 누락 | `sector-analyst` |

앞 단계 값이 틀려 4–7절까지 틀렸다면 책임은 앞 단계 하나로 적는다. 분석가는 앞 단계가 고쳐진 뒤 다시 불린다.

## 하지 말 것

- `dossier.md`, `brief.md`, `chrome-findings.md`를 고치지 않는다.
- 다른 섹터의 결론을 근거로 이 섹터를 판정하지 않는다.
