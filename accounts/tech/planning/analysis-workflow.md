# 분석 워크플로

← [tech.archive](../README.md)

뉴스를 **요약**하는 일과 **분석**하는 일을 나눕니다. 요약은 원문을 줄이는 것이고, 분석은 맥락·영향·한계를 더해 독자가 판단할 수 있게 하는 것입니다. 분석 자료(dossier)를 먼저 확정하고, 슬라이드 문안은 별도 단계에서 만듭니다.

## 6단계

| 단계 | 할 일 | 결과 |
|---|---|---|
| 1. 후보 수집 | 공식 발표, 뉴스 매체, 논문에서 후보와 원문 URL 확보 | 후보 목록 |
| 2. 중복 제거·평가 | 같은 사건 묶기, 아래 5점 평가 | 우선순위 |
| 3. 원문 조사·사실 검증 | 1차 출처 확인, 수치·날짜·핵심 주장 대조 | 검증 기록 |
| 4. 맥락 분석 | 이전과 달라진 점, 배경, 기대 효과, 한계 | dossier 본문 |
| 5. 각도 결정 | 지금 게시할 이유와 핵심 메시지 | 게시물 각도 후보 |
| 6. 결정 | 게시 / 추가 조사 / 보류 / 폐기 | 최종 결정 |

## 선별 점수표 (T04)

각 항목 1–5점. 점수는 후보 간 **우선순위**를 정하는 도구일 뿐입니다.

| 항목 | 확인할 질문 |
|---|---|
| 시의성 | 지금 다뤄야 할 이유가 있는가? |
| 영향력 | 기술·산업·일상에 미칠 영향이 큰가? |
| 독자 관련성 | AI에 관심 있는 한국어 독자가 이해하고 활용할 가치가 있는가? |
| 새로움 | 이미 알려진 것과 무엇이 다른가? |
| 설명 가치 | 배경과 의미를 붙였을 때 제목 전달 이상의 가치가 생기는가? |

## 통과 조건 (점수와 별개)

점수가 높아도 아래를 못 넘으면 게시하지 않습니다.

- 핵심 주장마다 **1차 출처**(발표 기관·논문·공식 문서) 또는 신뢰할 만한 보도 2곳 이상
- 모든 수치에 **출처 URL과 날짜**. 기준(예: “연환산 매출”, “퍼센트포인트 vs 퍼센트”)을 원문 그대로 표기
- 회사 자체 발표·자체 벤치마크는 “○○ 발표 기준”으로 명시
- 확인이 안 된 주장은 “미확인”으로 표시하고 본문 근거로 쓰지 않음

## 출처 표기 원칙 (T06)

- 원문을 길게 옮기지 않고, 검증한 사실을 우리 말로 해설한 뒤 출처를 밝힌다.
- 리포트·기사 속 차트는 그대로 쓰지 않는다. 필요하면 수치를 확인해 새로 그린다.
- 인용은 짧게, 따옴표와 출처를 함께.
